# 人工评测量表

每个 profile 分别抽取可回答、歧义、证据不足与不可回答案例。两名评审者分别打分，在修改模型或阈值前把分歧记下来；中英文 dev 与 test 不交叉复用问题。

## 可回答性标签怎么判

- `answerable`：固定快照中至少有一段原文直接给出所问事实或解释；必须填写 reference answer 和 gold chunk。
- `ambiguous`：问题存在多个合理解释或要求偏好选择，而语料没有给出消歧条件或统一判断标准；不能靠任选一种解释作答。
- `insufficient`：语料确实谈到了同一主题，但缺少问题要求的具体型号、算法、数值或因果依据。
- `unanswerable`：问题落在固定语料范围之外，或依赖天气、汇率等快照没有收录的实时信息；没有可作为答案依据的相关段落。

`gold_chunk_ids` 按检索 qrels 使用：凡是在脱离相邻 chunk 后仍能独立说清“对象是谁、事实是什么”的片段都应标为相关；同一事实若出现在两个不同原文位置，两处都标。滑动窗口重叠带来的半句副本若缺少主语或型号上下文，则不重复计入。MRR 看第一个相关片段的位置，Recall 则衡量标注相关片段被找回了多少；后者不是“回答至少需要几段证据”的含义。

标注时先找直接支持段落；找不到时，再用上面的顺序区分“问题本身没有唯一解释”“主题相关但细节缺失”和“语料范围之外”。后三类都不填写 gold chunk 或 reference answer。

| 维度 | 0 | 1 | 2 |
| --- | --- | --- | --- |
| 检索支持 | 缺少标准证据 | 证据相关但不完整 | 检索到直接支持的证据 |
| 引用支持 | 引用缺失或无关 | ID 有效但支持不完整 | 引用直接支持展示的答案 |
| 拒答 | 不安全地回答或无必要地拒答 | 决策处于边界 | 正确回答/拒答，且理由清晰 |
| 答案清晰度 | 有误导性 | 可理解但含糊 | 简洁且边界明确 |

记录案例 ID、profile、语料清单哈希、实际索引哈希与范围、Git revision、检索配置和评审理由。新的模型、分块参数、RRF 权重与拒答阈值必须先在对应 profile 的开发集确定；当前 test 快照只用于回归报告。若扩展 test，则提升 profile / protocol 版本、保留旧快照，并为新的泛化结论另建未查看的封存测试集。

`citation_valid` 只检查 ID 是否属于本次 evidence，不计作“引用支持”满分。原文相关但没有回答所问细节时，“检索支持”最多 1 分；只有 passage 直接给出答案，才能把它记为语义支持。
